The product

What you are presenting

SkillBridge Guinea is a local services marketplace for Guinea. It solves a simple problem: finding a trustworthy electrician or plumber is hard, and skilled workers struggle to reach new customers.

For customers

Find and book

Search by trade, city and rating. Compare profiles and reviews. Send a free booking request. Track it from the dashboard.

For professionals

Win work

Create a profile, show experience and a starting rate, accept or decline requests, and mark jobs as completed.

For admins

Keep it trustworthy

Suspend bad accounts, remove inappropriate reviews, and inspect bookings across the platform.

What it is — and what it is not

It is: a working Laravel + MySQL web app, running locally, with real database storage, authentication, roles, bookings, reviews and notifications.

It is not: a payment platform, a cloud-hosted product, or a production service. There is no online payment by design — customer and professional agree directly.

The demo database has 6 trades, 4 professionals, 7 bookings and 2 reviews. The interface is in French; the main screens have an English toggle and a light/dark theme.

Start the app

Open a terminal in the project root (the folder that contains sample/), then run:

$ cd sample $ ./vendor/bin/sail up -d $ ./vendor/bin/sail artisan migrate --seed

On Windows, use an Ubuntu/WSL2 terminal and run the same commands from the project folder. Full Windows steps are in docs/windows-setup.md.

First time only: if dependencies are missing, run composer install and ./vendor/bin/sail npm install first.

If someone asks

What to say about the code

You do not need to read code during the demo. Use the plain-English answers below. The app is a standard Laravel application: a URL goes to a route, the route calls a controller, the controller uses a model to read or write MySQL, and a Blade view renders the HTML.

The request flow, in one picture

Browseryou click a link or submit a form
Routeroutes/web.php maps the URL
Controllervalidates and decides what to do
Modelreads/writes the MySQL tables
Blade viewturns data into HTML

Example: opening /search calls SearchController, which queries the users, worker_profiles and reviews tables, then renders resources/views/search.blade.php.

Where everything lives

If they ask…Open thisIn plain English
Where are the URLs?routes/web.phpThe map of every page and action.
Where is the page logic?app/Http/Controllers/One class per area: booking, search, admin, auth, notifications.
Where are the database tables?app/Models/Each model represents one table: User, WorkerProfile, Booking, Review, Trade.
Where is the HTML?resources/views/Blade templates for every page, layout and component.
Where is the table structure?database/migrations/The recipe that creates the MySQL tables.
Where is the demo data?database/seeders/Trades and demo accounts/bookings/reviews.
Where is the design?public/assets/css/style.css + resources/views/The shared look and the page markup.
Where are the tests?tests/Feature/ and tests/Unit/98 automated checks covering the flows.
Where is the plan?docs/backend-plan.mdThe original design decisions and milestones.

“How does a booking work?”

The customer submits the form → StoreBookingRequest validates it → BookingController creates a Booking row with status pending → the worker gets a notification → the worker accepts/declines → the status changes → the customer can review after completion.

“How do you stop abuse?”

Passwords are hashed, forms use CSRF tokens, login and password reset are rate-limited, routes use auth and role middleware, and policies check ownership before a booking can be accepted, completed, cancelled or reviewed. Suspended users are blocked and logged out.

Best sentence if you get stuck: “The app is built with Laravel and MySQL. The code is organised into routes, controllers, models and Blade views, and the flows are covered by automated tests.”

The data

Where the database is

The short answer: the data lives in a MySQL 8 database running inside Docker. It is not a file on the Desktop. The app connects to it using the settings in .env.

Connection settings

SettingValueMeaning
Database typeMySQL 8.4Same as the original project design.
Host (inside Docker)mysqlThe name of the MySQL container.
Port3306Also exposed to the laptop on 127.0.0.1:3306.
Database nameskillbridgeWhere all app tables live.
UsernamesailDevelopment user.
PasswordpasswordDevelopment password (not a production secret).

These values come from sample/.env. Do not change them during the demo.

Show the data from a terminal

From the sample/ folder:

$ ./vendor/bin/sail mysql # inside MySQL: SHOW DATABASES; USE skillbridge; SHOW TABLES; SELECT id, name, email, role FROM users; SELECT id, status, description FROM bookings; exit;

This opens the MySQL client inside the Docker container. Type exit to leave.

Show the data without SQL

The easiest option is the app itself: log in as admin and open Administration. The Utilisateurs, Avis and Réservations tabs show the same data in a human-friendly way. Use this in the demo; use SQL only if a lecturer asks to see the raw tables.

What is in each table

TableWhat it stores
usersEvery account: customers, professionals and the admin. Passwords are hashed, never stored as plain text.
tradesThe six categories: electrician, plumber, mason, mechanic, carpenter, painter.
worker_profilesA professional’s bio, experience, service area, starting rate, availability and verification.
bookingsCustomer requests: who, which professional, description, date, address, status.
reviewsOne rating and comment per completed booking.
notificationsThe in-app inbox: new request, accepted, declined, completed, cancelled, new review.
sessions, cache, jobsLaravel plumbing for logins, caching and background jobs. Ignore during the demo.

Where is the data physically?

It is stored in a Docker volume attached to the MySQL container. The volume is created by Docker Compose and normally named after the project plus sail-mysql. It survives restarts of the app; it is removed only if you delete the volume or run a reset command.

You do not need to open the volume. Use the MySQL client or the admin panel.

Reset the demo data

If a demo changes too much data, restore the original seed:

$ ./vendor/bin/sail artisan migrate:fresh --seed
Warning: migrate:fresh deletes every table and re-creates it. Never run it in the middle of a presentation unless you intend to wipe the demo data.

Questions

Questions and answers

Short answers for the questions a lecturer or friend is most likely to ask.

Is it secure?
Passwords are hashed, forms are protected against CSRF, login and password reset are rate-limited, routes require authentication and the right role, and policies check ownership before a booking can be accepted, completed, cancelled or reviewed. Suspended accounts are blocked at login and logged out of active sessions.
Does it handle payments?
No, by design. SkillBridge connects people; the customer pays the professional directly after the job. This avoids handling money and card data in a student project.
Is it mobile-friendly?
Yes. The layout is responsive: navigation collapses, cards stack, and tables become labelled cards on small screens. You can show this by narrowing the browser window during the demo.
Does it support English?
The interface has a French/English toggle and a light/dark theme. The main customer, worker and admin screens switch to English; a few newer screens (such as profile editing) and server-side validation messages are still French. Full server-side translation is documented as future work.
What if two customers book the same professional?
Both requests are stored. The professional chooses which one to accept or decline. There is no live calendar or automatic slot locking in this version; that is a reasonable next feature.
How many users can it handle?
It is a local FYP demo, not load-tested. The stack (Laravel + MySQL) can scale, but no production capacity claims should be made. The honest answer is: “It has not been load-tested; this is a local demonstration.”
Is it deployed online?
No. It runs locally in Docker for the FYP demo. The static design prototype was shared earlier via Cloudflare R2, but the Laravel app itself is not hosted.
How do you know it works?
There are 98 automated feature tests covering registration, login, roles, search, booking, cancellation, reviews, admin actions, profile editing, password reset and notifications. The test suite runs on SQLite locally and MySQL 8.4 in GitHub Actions.
Why Laravel and MySQL?
Laravel gives us authentication, validation, security defaults, database migrations and testing in one framework. MySQL matches the relational design from FYP1. Blade keeps the front end simple — no separate JavaScript app to maintain — and Docker/Sail makes it run the same way on Linux and Windows.
What is missing or next?
Admin verification of professionals, reporting/hiding reviews, SMS notifications, queued email, full server-side translation, and production hosting. None of these block the local demo.

Recovery

If something goes wrong

Most problems are caused by Docker not running or the app not being started. Work through this table.

SymptomWhat to do
localhost:8000 does not openStart Docker Desktop. In sample/, run ./vendor/bin/sail up -d, then ./vendor/bin/sail ps.
“500” error pageRun ./vendor/bin/sail logs and check sample/storage/logs/laravel.log. Often the database is not running.
Database connection errorRun ./vendor/bin/sail ps. If MySQL is not up, run ./vendor/bin/sail up -d. Confirm DB_HOST=mysql in .env.
Login failsUse the exact demo email and password password. Clear cookies or use a fresh incognito window.
“Too many attempts”Wait one minute, or run ./vendor/bin/sail artisan cache:clear.
Data is missing or changedRestore the seed with ./vendor/bin/sail artisan migrate:fresh --seed (this wipes data).
Page looks unstyledHard refresh: Ctrl + F5 (Windows) or Cmd + Shift + R (Mac).
Port 8000 is busyRun ./vendor/bin/sail down, then ./vendor/bin/sail up -d. Or change APP_PORT in .env and restart.
“Page expired” / CSRFRefresh the page and submit the form again. Do not leave forms open for a long time.
Everything is brokenRun ./vendor/bin/sail down, then ./vendor/bin/sail up -d, then reseed if needed.

Useful commands (from the project root)

$ cd sample $ ./vendor/bin/sail ps $ ./vendor/bin/sail logs $ ./vendor/bin/sail artisan cache:clear $ ./vendor/bin/sail artisan migrate:fresh --seed

Do not do during the demo

  • Do not run migrate:fresh while presenting.
  • Do not suspend the admin, Amadou or Mamadou.
  • Do not delete the seeded 5★ reviews if you want to show ratings.
  • Do not edit .env or close the terminal running Sail.
  • Do not use the browser Back button after submitting a form; use the app’s links.
